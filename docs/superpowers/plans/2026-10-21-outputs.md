# Read-only outputs (v0.14.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a Prometheus metrics file with the snapshots, ship a Grafana dashboard and Prometheus examples, and add a printable, redacted executive page (EN/IT) that honours `?team=`. No outward writes.

**Architecture:**

- **Design first:** the executive page is drawn in Claude Design (Primer Hub design system) and approved by the owner before any UI code (Task 0). Approved deviations go into "Mockup decisions" and win over the defaults in Tasks 6–7.
- **Metrics:** a pure renderer `renderMetrics(index, metricsPolicy)` in the collector. `writeSnapshots` writes its output to `metrics/hub.prom` through the same publication gate. Gauges only, no timestamps, no repository/component/team label, unknown = series omitted plus `hub_project_measure_known 0`.
- **Executive view:** a pure model in `src/lib/executive.ts` turns `index.json`, `history.json` and `changes.json` into a small redacted input and then into numbers. A pure text layer turns numbers into sentences. The page pre-renders the whole-portfolio view; a small client script re-runs the same pure functions on the team-filtered subset from a JSON data block. No fetch, no team text printed.
- **Examples and docs:** `examples/grafana/`, `examples/prometheus/`, `docs/outputs.md` + IT mirror.

**Tech Stack:** Astro 7, TypeScript 6, Zod, Vitest, Playwright. No new runtime or dev dependency.

**Spec:** `docs/superpowers/specs/2026-10-21-outputs-design.md` (IT mirror under `docs/it/`). Read the "Release split" box, §5.1–§5.4, §5.6–§5.8 and §10 first. §5.5 (notifications) is **out of scope** (v0.15.0). Section numbers (§) refer to the spec.

## Global Constraints

- **Unknown is never 0** (spec D3): a numeric metric series is omitted when unknown; on the page an unknown count is "not measured" or "≥ n", never "0".
- **Redaction (spec §5.1, D14):** the executive page, in both audiences, never contains a repository name, component id, alert id or title, exception id, image name or digest, package or license name, team reference (`org/slug`), team slug as visible text, a `github.com` link or an error detail. Links point only to hub pages.
- **Metrics never contain** (spec §5.3.3): repository, component, environment, workflow, alert, exception, image, package, license, team or user labels; titles; URLs; error details; business unit; provider base URLs.
- **No team label in metrics** (spec D18, §10 decision 4).
- **Static site:** CSP unchanged (`script-src 'self'`, `connect-src 'self'`). No inline executable script; a `<script type="application/json">` data block is allowed. Values reach the DOM with `textContent`, never `innerHTML`.
- **Primer tokens and Octicons (ADR 0009):** status always as the status icon + word (v0.13.0 `StatusDot`), never colour alone. WCAG 2.2 AA. Tables with `<caption>` and `<th scope>`.
- **Language:** every UI string EN + IT (`tests/unit/i18n.test.ts` parity); every doc EN + IT (plans excepted). Singular/plural through the existing `plural({ one, other }, n)` helper in `src/lib/workflows.ts` and `xOne`/`xMany` keys.
- **Synthetic data only:** `example-org`, `project-alpha`… No real company, team, line or project names. Never name the protected hosting domain.
- **Never run `npm run ci:build` or `npm run collect:mock`**: they overwrite `public/data`, the owner's real snapshot (git-ignored).
  - Goldens: `npm run fixtures:update` (writes `fixtures/snapshots`).
  - Manual build: `SNAPSHOT_DIR=fixtures/snapshots npx astro build --outDir "$(mktemp -d)"`.
- **Never use or kill port 4321.** For e2e: `sed 's/4321/4377/g' playwright.config.ts > playwright.tmp.config.ts && npx playwright test -c playwright.tmp.config.ts`, then delete `playwright.tmp.config.ts` and `.e2e-dist/`. Never commit them.
- **Containers:** Podman only.
- **Commits:**
  - Conventional Commits, made with `git -c user.name=massilp -c user.email=3519719+massilp@users.noreply.github.com commit`.
  - No attribution trailers.
  - Run `npx prettier --write` on touched files before each commit.
  - Push, PR, merge and release only with the owner's OK; push to `origin` only, never `emu-archive`.
- **Design canvas:** after UI changes, update the Claude Design canvas. Claude Design links never go into the repo.

3. **History with fewer entries than `trendDays`, or with projects added later.** Expected: the comparison column says "Not enough history"; a project missing from an older entry is not counted in any status of that column (the Projects row shows the smaller number). Pinned in Task 5.
4. **A project name containing a canary secret, or a catalog repository name anywhere in the page.** Expected: the metrics write is refused by `assertPublishable` (the collection fails loudly, like the snapshots); the executive page never prints a repository name. Pinned in Tasks 3 and 6.
5. **`outputs.executive.enabled: false` or `outputs.metrics.enabled: false`.** Expected: no `executive/` pages in either language and no nav entry; no `metrics/hub.prom`, and the Data quality line says "off". Pinned in Tasks 3 and 6.

### Task 2: Prometheus renderer

**Files:**

- Create: `collector/src/outputs/prometheus.ts`
- Test: `tests/unit/prometheus.test.ts`

**Interfaces:**

- Consumes: `Policies['outputs']['metrics']` (Task 1); `PortfolioIndex`, `ProviderStateSchema`, `DimensionSchema`, `HealthStatusSchema` (`@model/index`).
- Produces:
  - `type MetricsTruncation = 'none' | 'dimensions' | 'portfolio-only'`
  - `interface RenderedMetrics { text: string; series: number; bytes: number; truncated: MetricsTruncation }`
  - `renderMetrics(index: PortfolioIndex, metrics: Policies['outputs']['metrics']): RenderedMetrics`
  - `METRIC_FAMILIES: readonly string[]`: the 25 family names of the §5.3.2 table, in table order (Task 4 uses it).

Format rules (spec §5.3.1–§5.3.4):

- Families appear in table order. Each family appears once: `# HELP <name> <one English line>`, then `# TYPE <name> gauge`, then its samples sorted by label string. A family with no sample still prints HELP and TYPE.
- Labels are sorted by name inside `{}`. Label values are escaped `\\`, `\"`, `\n`.
- Numbers are printed with `String(n)`. Lines end with `\n`, and the file ends with a newline. No timestamps. `bytes` is the UTF-8 length.

Values that need a rule beyond the table:

- `hub_collection_timestamp_seconds` = `Date.parse(index.generatedAt) / 1000`.
- `hub_provider_state`: one-hot over `ProviderStateSchema.options` (`off`, `available`, `partial`, `not-authorised`, `unknown`), for each key of `index.run.providers`.
- `hub_project_dimension_status` reads the top-level dimension fields of the index entry. `delivery`, `version`, `security` and `governance` are statuses; `coverage` and `quality` are objects, so take `.status`.
- `hub_project_measure_known` measures, in this order:
  - `score`;
  - `open_alerts`: known only when critical, high, medium and low are all non-null;
  - `overdue_alerts`: known when `risk.overdue` is non-null;
  - `controls_coverage`, `quality_coverage`;
  - `sbom` (`supplyChain.sbomAvailable`), `unsigned_images`, `flagged_licenses`.
- Truncation (§5.3.4):
  1. Render everything.
  2. Over `maxBytes`: render again without `hub_project_dimension_status` (`'dimensions'`).
  3. Still over: render only `hub_info`, `hub_collection_*`, `hub_projects`, `hub_portfolio_projects`, `hub_provider_*` and `hub_metrics_truncated` (`'portfolio-only'`).
  - `hub_metrics_truncated` is 1 in both truncated cases.

**Interfaces:**

- Produces from `src/lib/executive.ts`. It imports nothing from Astro, the DOM or Node, because it ships in the client bundle.
  - `interface ExecProject`:
    - identity: `id: string`, `name: string`, `teamSlugs: string[]`;
    - status: `overall: HealthStatus`, `dims: Record<Dimension, HealthStatus>`, `score: number | null`;
    - alerts: `open: { critical: number | null; high: number | null }`, `countsComplete: boolean`, `secrets: number | null`;
    - remediation: `overdue: number | null`, `overdueCriticalHigh: number | null`, `accepted: number | null`, `exceptionIssues: number`;
    - supply chain: `supplyChain: { repositories: number | null; sbomAvailable: number | null; unsignedImages: number | null; flagged: number | null }`;
    - `collectionErrors: number`;
    - `direction: 'worse' | 'better' | null`, from `changes.json` (`previous.overall` vs `current.overall` by `healthRank`); null unless `changes.basis.state === 'compared'`;
    - `past: { compare: HealthStatus | null; start: HealthStatus | null }`, null when the project is absent from that history entry.
  - `interface ExecInput { generatedAt: string; dataSource: string; projects: ExecProject[]; trend: { state: 'ok' | 'none' | 'off'; now: string | null; compare: string | null; start: string | null; trendDays: number }; topRisks: number }`
  - `toExecInput(index: PortfolioIndex, history: HistoryFile | null, historyEnabled: boolean, changes: ChangesFile | null, outputs: Policies['outputs']['executive'], now: Date): ExecInput`
    - `trend.compare` = the `collectedAt` of the newest entry with `collectedAt ≤ now − trendDays`, else null;
    - `trend.start` = the oldest entry;
    - `trend.state` = `'off'` when history is disabled, `'none'` when it is missing or has no entries.
  - `filterInput(input: ExecInput, teams: string[]): ExecInput`: keeps the projects passing `teamMatch(teams, p.teamSlugs)` from `src/lib/portfolio-filters-core.ts`. `[]` returns the input unchanged.
  - `type Bound = { n: number; lower: boolean } | null`: null = not measured; `lower` = print "≥".
  - `type RiskKind`: the 11 kinds of spec §5.6 point 4, in table order.
  - `interface ExecView`:
    - `total: number`, `tiles: Record<HealthStatus, number>`;
    - `trend: ExecInput['trend'] & { rows: Record<HealthStatus | 'projects', { now: number; compare: number | null; start: number | null }> }`;
    - `risks: { id: string; name: string; overall: HealthStatus; direction: 'worse' | 'better' | null; kinds: RiskKind[]; counts: Partial<Record<RiskKind, Bound>> }[]`;
    - `riskCandidates: string[]`;
    - `remediation: { overdue: Bound; overdueCriticalHigh: Bound; projectsWithOverdue: number; accepted: Bound; exceptionIssues: number }`;
    - `supplyChain: { sbom: Bound; repositories: Bound; unsigned: Bound; flagged: Bound }`.
  - `buildExecutiveView(input: ExecInput): ExecView`
    - `riskCandidates` = the ids of every red, grey or amber project, in risk order;
    - `risks` = the first `topRisks` of them.
- Produces from `src/lib/executive-text.ts`:
  - `type ExecStrings = typeof en.executive`
  - `interface ExecText { lede: string; trendSentence: string; risks: { id: string; sentences: string[] }[]; remediation: string; exceptions: string; supplyChain: string; filtered: (n: number, m: number) => string }`
  - `executiveText(view: ExecView, s: ExecStrings, fmtDate: (iso: string) => string): ExecText`
  - `execDateFormatter(locale: 'en' | 'it'): (iso: string) => string`, using `Intl.DateTimeFormat(locale === 'it' ? 'it-IT' : 'en-GB', { day: 'numeric', month: 'short', year: 'numeric', timeZone: 'UTC' })`. Server and client both use it, so the dates match.

Rules the signatures do not fix:

- **Risk order** (spec §5.6 point 4): red, then grey, then amber. Inside a group: more open critical first, then more open high (null counts as −1), then lower score (null last), then id.
- **Risk kinds** use the conditions of the spec table: the first matches in table order, at most three.
  - `critical-open` carries `lower` when `countsComplete` is false, printed as "≥ {n}".
  - `partly-visible` uses `{n}` = `collectionErrors`.
- **Sums (`Bound`):** add the known values. `lower` is true when some project's value is null and at least one is known. All null gives null.
- **Trend rows:** count projects by `overall` in each column. A column without an entry has `null` cells.
- **`trendSentence`:**
  - compares `start` with `now` for red, e.g. "Red projects: 0 → 2 since 3 Jan 2026.";
