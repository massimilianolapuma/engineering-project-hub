# Outputs (v0.11.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three outputs that read only what the collector already validated and published:

- a static Prometheus metrics file `metrics/hub.prom` published with the snapshots, plus a Grafana dashboard JSON and scrape examples;
- an opt-in, dry-run-by-default notification job that posts a sanitised digest of significant changes (from `changes.json`) to Microsoft Teams (Workflows webhook), Jira (create issue) and Azure DevOps (create work item);
- a printable executive page (EN/IT) with status counts, trend, top risks in plain words and overdue counts, without repository names or links into source systems.

**Architecture:**

- **Model/config:** policies gain an optional `outputs` block; a new `<configDir>/notifications.yaml` with its own strict Zod schema and generated JSON Schema. No snapshot, history or changes schema change.
- **Collector:** a pure `renderMetrics` in `collector/src/outputs/prometheus.ts`, written by `writeSnapshots` through the publication gate.
- **Notifier:** a separate program under `notifier/` (digest, renderers, POST-only client, ledger, CLI `scripts/notify.ts`), never importable from `collector/**` or `src/**`, run by a separate reusable workflow `notify.yml` whose only step with target secrets is "Notify".
- **Site:** `src/lib/executive.ts` (pure) and `src/pages/[...lang]/executive.astro`, print CSS in `src/styles/global.css`.

**Tech Stack:** TypeScript 6, Zod 4, Node `fetch` / `crypto` / `fs`, `yaml` 2.9, Astro 7, Vitest, Playwright. **No new dependency.**

**Spec:** `docs/superpowers/specs/2026-10-21-outputs-design.md` (IT mirror under `docs/it/`). Read it first. This plan does not repeat its rationale. Section numbers (§) and decision ids (D1–D16) refer to the spec.

## Global Constraints

- **Never run `npm run ci:build` or `npm run collect:mock`**: they overwrite `public/data` (the owner's real snapshot, git-ignored).
  - Goldens: `npm run fixtures:update` (mock provider, `GOLDEN_NOW = 2026-01-15T12:00:00.000Z`, writes only `fixtures/snapshots`).
  - Site tests build from `fixtures/snapshots` (`tests/integration/site.test.ts` sets `SNAPSHOT_DIR`).
  - A manual collection: `npx tsx collector/src/index.ts --source mock --out "$(mktemp -d)" --now 2026-01-15T12:00:00Z`.
  - A manual site build: `SNAPSHOT_DIR=fixtures/snapshots npx astro build --outDir "$(mktemp -d)"`.
  - A manual notifier run: `HUB_NOTIFICATIONS=dry-run DATA_SOURCE=mock npx tsx scripts/notify.ts --snapshots fixtures/snapshots --config config --out "$(mktemp -d)"`.
- **Never use or kill port 4321.** For e2e: `sed 's/4321/4377/g' playwright.config.ts > playwright.tmp.config.ts`, `npx playwright test -c playwright.tmp.config.ts`; delete `playwright.tmp.config.ts` (and `.e2e-dist/` if created) afterwards; never commit them.
- **Notification tests never touch a real endpoint.** Use the injected `fetch` of `postOnce` (a recording stub returning canned `Response`s), or a local `node:http` server on `127.0.0.1` with an ephemeral port only to prove that `http:` is **refused** before any request. No test may contain a real webhook URL, Atlassian site, Azure DevOps organisation or token; use `example.atlassian.net`, `example-org`, `https://prod-00.westeurope.environment.api.powerplatform.com/powerautomate/automations/direct/workflows/0000/triggers/manual/paths/invoke?sig=exampleSig` (synthetic). Canaries only from `tests/helpers/canaries.ts`.
- Outward writes: only `POST` to the documented endpoints (§5.5.4), only to the target allowlist, only from the "Notify" step. Nothing in this release writes to a monitored repository or to a source system. The collector stays GET-only.
- Unknown ≠ 0 everywhere: omitted metric series + `hub_project_measure_known 0`; "≥ n" for incomplete counts; "Not measured" for absent overdue data.
- Redaction (D9, D14): no repository name, component id, alert id/title, GitHub URL or error detail in the metrics, the digest, the payloads or the executive page — in **either** audience.
- Defaults verbatim from the spec:
  - `outputs.metrics: { enabled: true, maxBytes: 2097152 }` (bounds 65 536–16 777 216);
  - `outputs.executive: { enabled: true, topRisks: 5, trendDays: 7 }` (bounds 1–10, 1–90);
  - notifications: `mode: dry-run`, `locale: en`, `siteUrl: null`, triggers as §5.5.1, `digest.maxProjects: 10` (1–50), every target `enabled: false`, Teams `allowedHostSuffixes: ['.environment.api.powerplatform.com']`;
  - HTTP: 20 s timeout, 64 KiB (65 536 bytes) response cap, no retry, `redirect: 'error'`;
  - Teams body cap 24 576 bytes; Jira `summary` and ADO `System.Title` ≤ 255 characters;
  - ledger ≤ 200 entries, artifact `hub-notify-ledger`, file `ledger.json`, zip entry cap 1 MiB (1 048 576), artifact cap 5 MiB (5 242 880), retention 90 days; payload artifact `notification-payloads`, retention 7 days.
- Secrets: `TEAMS_WEBHOOK_URL`, `JIRA_EMAIL`, `JIRA_API_TOKEN`, `AZDO_PAT` — only in the Notify step env, added to `sensitiveEnvValues()`, never logged, never in errors or files.
- Policies `schemaVersion` stays `'1.0'`; `notifications.yaml` `schemaVersion: '1.0'`; ledger `schemaVersion: '1.0'`.
- Every UI and notification string is EN + IT (parity: `tests/unit/i18n.test.ts`). Every new or changed doc has an EN and an IT version.
- Containers: podman only (none are needed here).
- Commits: Conventional Commits, `git -c user.name=massilp -c user.email=3519719+massilp@users.noreply.github.com commit`, branch `feat/outputs`. Run `npx prettier --write` on touched files before each commit. Do not push until Task 9, and only when the orchestrator says so.

## Review Focus

1. **A mock or uncompared change set can never be sent.** Mode resolution returns `dry-run` with the first failing reason for each of: config `mode: dry-run`, `HUB_NOTIFICATIONS` unset/`dry-run`, `DATA_SOURCE=mock`, `run.dataSource=mock`, `basis.state≠compared`, `basis.synthetic=true`. In dry-run the fetch stub records **zero** calls. Pinned in Task 6.
2. **No duplicates.** Same significant items with a different `generatedAt` → same `changeSetKey` → `skipped-duplicate` when the ledger has it; ledger restore `failed` in send mode → nothing sent, exit 1. Pinned in Tasks 5 and 6.
3. **Secrets stay in one step.** Parsed workflow YAML: the four secret names appear only under the Notify step `env` of `notify.yml` and in the caller's `secrets:` mapping to `notify`; never in `collect-data.yml`, `build`, `attest`, `deploy`. Pinned in Task 7.
4. **Host pinning.** `http:`, a foreign host, `user@host`, a Teams URL on `logic.azure.com`, a Jira path outside `baseUrl`, an ADO host other than `dev.azure.com`, and a 3xx response all end without a second request and with fixed messages; nothing is logged. Pinned in Task 6.
5. **Unknown is never 0.** Gamma has no `hub_project_score` / `hub_project_open_alerts` series and `hub_project_measure_known{…} 0`; the executive page says "Not visible" / "≥" / "Not measured", never "0 alerts" for Gamma. Pinned in Tasks 2, 3 and 8.
6. **Nothing internal leaks.** `example-org/` never appears in `fixtures/snapshots/metrics/hub.prom`, in any payload file, or in `dist/executive/index.html` / `dist/it/executive/index.html`; `github.com` never appears in the executive HTML. Pinned in Tasks 3, 6, 8.

- Families, labels and unknown handling exactly as spec §5.3.2; fixed family order: `hub_info`, `hub_collection_timestamp_seconds`, `hub_collection_duration_seconds`, `hub_projects`, `hub_portfolio_projects`, `hub_project_status`, `hub_project_dimension_status`, `hub_project_score`, `hub_project_open_alerts`, `hub_project_open_alerts_complete`, `hub_project_overdue_alerts`, `hub_project_controls_coverage_ratio`, `hub_project_quality_coverage_ratio`, `hub_project_collection_errors`, `hub_project_measure_known`, `hub_metrics_truncated`.
- Inside a family: series sorted by the label string (labels themselves in alphabetical order inside `{}`).
- Numbers: integers as `String(n)`; ratios with at most 4 decimals (`Number(x.toFixed(4))`); seconds of duration with at most 3 decimals.
- `collector_version` is accepted only if it matches `^\d+\.\d+\.\d+(-[0-9A-Za-z.]+)?$`; otherwise the label value is `unknown`.
- `overdue` values: read `p.risk?.overdue` / `p.risk?.overdueCriticalHigh`; absent field → series omitted and `measure_known{measure="overdue_alerts"} 0`.
